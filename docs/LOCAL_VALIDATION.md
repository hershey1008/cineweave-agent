性能协议为 **本机 CPU、规则解析、10 条混合查询预热后的 200 次请求**，计时包含消息请求本身，创建会话不计入。它不代表冷启动、全新查询、外部 LLM、远程部署或大规模负载成绩。该性能实验执行时未配置真实 LLM，不能据此声称 LLM 延迟达标。

## 真实 LLM 联调与超时修复

用户配置 API 后，单轮真实请求已联通。追问“轻松一点，其他要求不变”复现 `ReadTimeout`，实测约 8.2 秒，对应原先写死的 8 秒请求超时。另一次回归在 20.01 秒被外层聊天截止中断。

修复为：LLM 首次解析与最多一次 JSON 修复共享可配置的 45 秒预算；连接上限 5 秒；聊天整体截止至少为 LLM 预算加 15 秒，避免旧 `.env` 的 `CHAT_TIMEOUT=20` 抢先取消；浏览器和代理上限均为 65 秒。超时不自动重试或伪装为规则成功；返回可区分的超时、鉴权、限流、协议错误，日志不包含密钥或上游响应正文。

提示词 `intent-v1.1` 明确“轻松”是软偏好，以及“第一部”默认指上一轮推荐列表，由后端解析序号并查询事实，不要求用户补充片名。

真实 LLM 五轮回归入口：`python evaluation/runners/verify_llm_conversation.py`；报告为 `evaluation/reports/generated/llm-live-regression.json`。早先规则模式测试成绩与真实 LLM 联调分开报告。

修复后通过前端 Nginx 代理实测 **5 / 5 轮通过**：首轮 12.92 秒；“轻松一点，其他要求不变”14.80 秒；替换第三部 8.20 秒；取消时长 9.21 秒；解释第一部 6.29 秒。每轮实际调用 LLM 一次，硬条件、排除列表与解释目标检查通过。该样本仅为小规模回归，不构成 P95 或稳定性成绩。

## 独立待办

- 真实 LLM 的多模型兼容性、大规模对话失败率和并发性能仍需专项评估；少量联调不替代完整评估。
- 120 条查询是待人工审核的输入草案，相关性等级尚未人工标注，不能报告 nDCG/Success 提升。
- 40 会话是规则模式功能 fixture，与开放对话满意度、真实 LLM 泛化能力区分。
- 数据类型隔离不能保证剩余电影关联全部正确；仍需更深入实体匹配核验。
- 原训练样本时间协议需要重建后，才能宣称新的推荐算法离线收益。
