## 开发顺序

先完成可独立验收的语义检索，再接混合推荐，随后加入 Agent 和前端。每一阶段先固定输入输出与失败行为，再写实现。这样可分别定位数据、检索、排序和对话问题。

首次迁入 FunRec 代码时检查上游许可证，保留版权和来源；只迁入实施所需源码。迁移前检查 `.env`、模型路径、数据路径、Docker 挂载和数据库备份策略。新表脚本只作用于新增表，不重置原业务表。

## 待部署前确定的配置

- LLM 服务商、型号、结构化输出能力、网络可达性与预算。
- 语义模型的固定 revision、推理库、运行硬件、模型缓存路径。
- 活动目录/索引版本和重建发布方式。
- 开发集调整后的候选预算、语义配额、排序权重。
- 实测超时配置与性能基线。

这些属于实施配置，不影响当前模块边界。未确定的值不能被写成已验证事实。

## V1 后续可选方向

- 更丰富、经核验的内容字段与多语言查询优化。
- Cross-encoder 会话重排，并评估增益与耗时。
- SASRec/HSTU 在线召回，与已有协同模型做统一协议比较。
- Semantic ID 生成式召回，作为独立候选通道。
- 在有真实反馈后开展偏好学习与多目标片单生成。

各方向单独提出问题、基线和验收目标，不将其计入 V1 已完成范围。
