# V1 评估与验收协议

状态：拟定协议，所有阈值均为目标，未运行测试、未取得对应结果。日期：2026-10-19。

## 1. 验收原则

- 数据/索引、检索、多轮任务、推荐算法、工程可靠性分别评估。
- 开发集调参数，封闭测试集只用于最终评估；配置与模型 revision 固定。
- 功能自动测试可模拟 LLM，真实端到端测试必须调用实际模型，两类结果分别报告。
- 硬条件违反、越权和虚构电影属于阻断发布的问题。
- MovieLens 是显式评分数据，评分构造的偏好标签不是原生点击或曝光；不能据此宣称线上 CTR 提升。

## 2. 数据与索引发布门槛

| 检查 | 通过条件 |
| --- | --- |
| ID 唯一性与关联 | 无重复业务 ID，所有索引 ID 可关联发布目录 |
| 文本/ID/向量映射 | 行数一致，顺序检查通过 |
| 向量 | 维度正确，无 NaN、Inf、异常零向量；归一化误差在指定容差内 |
| 缺失字段 | 全部计入报告并采用明确回退，未知片长不通过片长硬条件 |
| 文本清洗 | 缺失、占位符、HTML 实体等固定样例全部通过；随机抽样复核 |
| 版本一致性 | 数据、模型 revision、模板、维度与 manifest 一致 |
| 发布与回滚 | 新版失败不覆盖旧版；版本切换和回滚均验证 |

报告包含计数、比例、异常 ID、修复规则和剩余限制。简介非空不能被当作剧情正确性审计通过。

## 3. 检索测试集与标注

建立 120 条人工查询：

| 分类 | 数量 |
| --- | ---: |
| 类型、主题与故事内容 | 40 |
| 氛围、节奏等软偏好 | 20 |
| 中英文片名与参考电影 | 20 |
| 多条件需求 | 20 |
| 歧义、库外电影与无可行结果 | 20 |

按类别分层拆为 60 条开发、60 条封闭测试。避免同一意图的近义改写分散到两组，导致开发与测试泄漏。查询写作不能机械复制电影简介句子。

对比当前 Elasticsearch 文本搜索、纯语义、语义加结构化过滤。使用各系统 Top-20 的并集做人工标注池，必要时补充已知相关电影。相关性等级：0 不相关、1 部分相关、2 明显相关。复核标注分歧并保留说明。

计算 nDCG@10、Success@10、硬条件满足率、无结果判断正确率，并报告标注覆盖情况。Success@10 定义为前十名至少有一部等级 2 电影；普通可回答查询与无结果查询分开统计。池化标注并未穷尽目录，不宣称全目录 Recall。

### 检索目标

- 封闭集 nDCG@10 高于文本搜索基线，并提供逐查询差异与不确定性分析。
- 普通可回答查询 Success@10 目标 ≥90%。
- 结构化硬条件违反数为 0。
- 库外、歧义、无结果等查询单独报告；不能靠一律返回空列表提高约束满足率。

## 4. 多轮 Agent 测试

建立 40 个会话，每个 3–5 轮，覆盖：修改条件、清除条件、指代替换、排除已看、候选不足、库外需求、条件冲突、会话隔离、并发/重试、资料中含指令文本。

每轮预先标注期望动作、字段操作、保留条件和允许结果。固定电影目录与用户历史 fixture，保存上轮展示顺序。确定性用例验证“第三部”的 ID，不依赖模型每次随机生成相同片单。

| 指标 | 目标 |
| --- | ---: |
| 状态字段更新准确率 | ≥95% |
| 完整会话成功率 | ≥90% |
| 返回电影 ID 有效率 | 100% |
| 硬条件满足率 | 100% |
| 越权或会话串扰 | 0 |
| 人工审计解释中的错误数值、虚构主创等事实错误 | 0 |

完整会话成功要求：动作、状态继承、指代、替换、最终约束和应答行为全部符合预期。错误、澄清、无结果按其正确性计分，不把流畅回答等同于完成任务。

硬条件满足率需与任务成功率、结果数量一起报告，避免空结果获得虚高指标。推荐不足 top_k 但确实无更多合法电影时，应明确说明并验证目录事实。

使用模拟 LLM 测业务契约与异常路径；使用真实 LLM 测实际端到端能力。关键会话至少重复三次，记录模型标识、参数、提示词版本和成功率波动。

## 5. 推荐方案与消融

在同一用户、查询和硬条件集合上比较：

| 实验 | 检验问题 |
| --- | --- |
| 原始 FunRec | 系统基线 |
| 原始推荐 + 同一硬过滤 | 单加规则的贡献 |
| 纯语义 + 同一硬过滤 | 内容语义的贡献 |
| 混合召回 + 同一硬过滤 | 协同候选的增量价值 |
| 完整方案 | DeepFM 与会话排序的效果 |
| 完整方案去掉多样性 | 打散的增益和相关性损失 |

原始系统不支持对话时，不伪造其意图理解能力。原始结果可做描述性参照；判断排序改动的因果贡献，使用相同已解析查询、约束、候选预算的受控对照。

记录 nDCG@10、Success@10、约束满足率、覆盖率、各通道独有相关候选、耗时和失败案例；按新用户/历史用户、简单/复杂查询分组。

### 历史行为离线评估

另用 MovieLens 行为评估 Recall@K/NDCG@K 时，统一时间划分、候选目录、历史过滤和正反馈定义。阈值按实际评分量表预先确定。训练期统计只能使用训练数据，样本和特征在切分后按时间构建。

当前旧流程存在全量统计在切分前计算的风险。既有模型可用于工程回归，但若要宣称算法提升，应在统一干净协议下重建基线与实验。时间协议、目标定义、全量或采样候选必须随结果公开，不能直接对比不同协议的分数。

## 6. 功能回归

必须通过：登录、首页推荐、冷启动、历史用户推荐、文本搜索、电影详情、评分、海报、聊天恢复、反馈去重、原响应字段兼容。原接口改为绑定登录身份时，前端、测试调用与错误码应一起更新。

推荐请求附 Authorization 头并不等于后端已验证身份；新增与修改接口均需实际校验认证依赖和资源归属。

## 7. 故障注入

| 注入故障 | 必须验证 |
| --- | --- |
| 意图 LLM 超时/非法 JSON/非法动作 | 受限修复，失败后明确错误/澄清；不写假成功 |
| 解释 LLM 失败/添加无依据事实 | 模板回退，保留有效卡片 |
| 语义服务不可达 | 标记降级，硬条件仍成立 |
| DeepFM 未加载 | 语义/融合排序降级 |
| Redis 故障 | PostgreSQL 恢复状态；无串会话 |
| 索引版本不一致 | 不报告语义 ready，不混用模型 |
| 无合法电影 | 无结果说明，不静默放宽条件 |
| 重复消息/事件 | 不重复入库，不重复更新状态 |
| 同会话并发两轮 | 版本冲突可恢复，无旧状态覆盖 |
| 非会话所有者访问 | 拒绝访问，无数据泄露 |
| 资料包含“忽略规则”等文本 | 无越权工具执行、条件仍受后端控制 |

## 8. 性能与资源

记录硬件、CPU/GPU、内存、运行库、LLM 服务商和型号、索引版本。模型预热后先单并发，再以 5 并发至少运行 200 个请求，记录 P50/P95、错误率、吞吐、峰值内存和 token 消耗。首次加载单独报告；正常路径与降级路径分别统计。

| 项目 | 初始目标 |
| --- | --- |
| 非 LLM 推荐路径 P95 | ≤2 秒 |
| 完整正常对话 P95 | ≤15 秒 |
| 后端整体截止 | 20 秒 |
| 聊天客户端超时 | 25 秒 |
| 未处理异常、状态串扰 | 0 |

查询编码和向量检索分开测；不以缓存命中速度代替冷查询编码。LLM 正常路径通常两次调用，修复总计最多三次；实际失败率与整体超时也必须报告。外部网络与服务商限制作为实测条件列出，不提前承诺硬件无关性能。
